## 这周先学什么

目标：用 5–10 分钟快速补齐应用层知识；只保留对 Agent 工程实践有解释力的内容。

### 1. 编码代理的开放后训练配方

- **学习深度**：理解原因
- **30 秒概念**：把编码代理能力拆成可复现的多阶段后训练流水线，从可验证奖励逐步过渡到软性评判信号。
- **为什么值得了解**：Rufus-Air 公开了包含 Coding Agent、Search Agent 等阶段的八阶段后训练配方，并记录了数据、奖励设计与阶段顺序。
- **用在哪里**：当团队要自建或微调编码代理时，可参考其阶段划分与奖励设计，而不是只关注最终模型分数。
- **应用层学到这里**：阶段顺序：SFT、推理 RL、编码 RL、指令遵循 RL、通用代理、编码代理、搜索代理、RLHF；奖励设计从硬可验证信号过渡到软性评判信号；数据与基础设施记录对可复现性的影响
- **动手建议（建议 20 分钟）**：用本地 Python 写一个玩具八阶段流水线模拟：每个阶段用字典记录输入数据量、奖励类型（硬/软）和预期能力，打印阶段顺序表。
- **完成标准**：输出一张包含八个阶段、奖励类型与能力目标的表格，并标注哪两个阶段使用软性奖励。
- **来源**：[来源 1](https://arxiv.org/abs/2609.29421)

### 2. 编码代理用于任务与运动规划

- **学习深度**：先知道
- **30 秒概念**：让编码代理自动生成任务与运动规划所需的专用工程代码，减少人工 TAMP 工程。
- **为什么值得了解**：一项研究探索编码代理能否自动化广义 TAMP 问题中的专用工程，说明编码代理正被用于机器人规划场景。
- **用在哪里**：在需要离散决策与几何约束耦合的规划问题中，可评估用编码代理生成规划代码的可行性。
- **应用层学到这里**：广义 TAMP 利用问题实例间的规律性；编码代理替代 TAMP 专用工程的可能性；离散决策与几何/运动学约束的耦合难点
- **动手建议（建议 20 分钟）**：用本地 Python 写一个玩具 TAMP 场景：两个方块、一个目标位置，用字典描述状态与动作，手动列出三条候选动作序列并标注哪条满足约束。
- **完成标准**：输出三条候选动作序列及约束满足标注，并说明哪条被选中。
- **来源**：[来源 1](https://arxiv.org/abs/2609.30233)

### 3. 移动规划代理的闭环 AI-for-AI 框架

- **学习深度**：理解原因
- **30 秒概念**：用闭环 AI-for-AI 框架让代理参与自身迭代开发，并在移动规划这类长程任务上验证。
- **为什么值得了解**：Qwen-Planner-Agent 提出闭环 AI-for-AI 框架，用于可扩展开发与迭代改进，并以移动规划作为高要求测试场景。
- **用在哪里**：当代理需要长期迭代改进且任务涉及多步工具调用时，可参考闭环开发与可靠性设计。
- **应用层学到这里**：闭环 AI-for-AI 的开发与迭代改进思路；移动规划作为长程、多步工具调用测试场景；代理可靠性在真实工作流中的重要性
- **动手建议（建议 25 分钟）**：用本地 Python 模拟一个移动规划闭环：给定三个地点与两个工具（地图、日历），用字典定义状态，手动走两步并记录一次失败恢复。
- **完成标准**：输出两步状态转移记录，并标注一次失败恢复的处理方式。
- **来源**：[来源 1](https://arxiv.org/abs/2609.29892)

### 4. 深度搜索代理的角色解耦与迭代合成

- **学习深度**：值得动手
- **30 秒概念**：把深度搜索代理拆成规划者与合成者等角色，并用摘要控制搜索历史噪声。
- **为什么值得了解**：IterSynth 针对 ReAct 式代理的角色耦合与上下文累积问题，提出角色解耦和基于摘要的迭代合成范式。
- **用在哪里**：在需要多步检索、证据整合与答案合成的搜索代理中，可用角色解耦减少单策略负担与历史噪声。
- **应用层学到这里**：角色耦合：单策略同时负责规划、证据使用与合成；上下文累积：搜索历史增长引入噪声；角色解耦与摘要式迭代合成
- **动手建议（建议 25 分钟）**：用本地 Python 写一个玩具搜索代理模拟：给定三篇小文档和两个角色（规划者、合成者），用字典传递摘要，手动完成一轮规划与合成。
- **完成标准**：输出一轮规划者摘要与合成者答案，并说明摘要如何减少历史噪声。
- **来源**：[来源 1](https://arxiv.org/abs/2609.29444)

### 5. 长程多智能体协作评测

- **学习深度**：先知道
- **30 秒概念**：用长程、多智能体协作任务评测 LLM 代理的协作能力，而非只聚合个体表现。
- **为什么值得了解**：AgentWorld 提出 100 个人工标注任务，覆盖 50 多轮交互与 3 至 20 个代理，用于评测长程多智能体协作。
- **用在哪里**：当设计多代理协作系统时，可参考其任务设计来区分真实协作能力与个体能力叠加。
- **应用层学到这里**：长程多智能体协作与短程竞争评测的区别；任务需要 3 至 20 个代理、50 多轮交互；避免仅聚合个体表现来代表协作能力
- **动手建议（建议 20 分钟）**：用本地 Python 写一个玩具多代理协作模拟：三个代理、五个回合，用字典记录每回合动作与协作得分，手动跑完并汇总。
- **完成标准**：输出五回合动作记录与协作得分汇总，并指出一次协作失败。
- **来源**：[来源 1](https://arxiv.org/abs/2609.31590)
