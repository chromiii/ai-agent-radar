# V2.2：自由提问与可实践的学习卡

目标是让个人学习路径完整：提出一个 Agent 应用层问题，阅读短卡，选择一个小练习，并能回到来源核对。

## 已实现

- `Ask Radar` 手动工作流接受 1–600 字自由问题，用已有 GitHub Secret 调用模型；学习卡显示在运行 Overview，也保存为 `answer.md`，检索与模型诊断保存为 `run.json`。新工作流合并后才出现在默认分支的手动运行入口。
- 周报和研究回答使用 `learning_cards.py` 的同一教学契约和渲染。卡片包含定义、应用场景、学习深度、2–4 个学习点、15–30 分钟的小练习、完成标准和来源。实践时间是建议预算，不能用字段校验保证实际时长。
- 研究评测增加学习卡结构检查、Markdown 回答、模型调用次数与已记录 token 用量。每完成一个场景就保存报告，后续运行中断也能保留已完成结果。
- 自由问题通过环境变量传入 Python，不插入 Shell 代码；用户和来源文字转义后展示。引用链接仍由程序从来源记录生成。

## 验证方式

```bash
python -m pytest -q
python research_eval.py --mode replay
python research_eval.py --mode live
python ask_radar.py --question "最近 MCP 有哪些值得学的实现？"
```

本地 76 项测试通过，包含不完整教学卡、过大的练习预算、编造链接、Markdown 内容边界、自由提问成功/失败记录和超长问题。八个合成回放通过。这些是结构与程序测试，不是八个真实答案的质量成绩。

PR 的 `research-live-suite` 标签触发八个 live 场景及一次 Weekly 预览；`ask-radar-preview` 标签触发一个自由提问示例。均限仓库所有者创建、且分支位于本仓库的 PR。Weekly 预览不提交报告、也不发送邮件。每次评测需要重新添加对应标签，提交代码不会自动消耗模型调用。

真实评测的结果与逐条阅读记录会在本阶段完成后补充。评估维度为问题相关性、引用支持、应用解释、练习范围，每项 0–2 分；这与自动结构 PASS 分开。资料仍是摘要和项目简介，未配置 Tavily 时覆盖有限。

## 后续边界

本阶段没有增加长期学习记忆、独立语义 Verifier、LangGraph、多 Agent 或 Web UI。下一轮按本次错误样本决定检索、核验或运行恢复的改进。日报与公司雷达保持现有运行路径；Weekly 只统一学习卡契约与呈现。
