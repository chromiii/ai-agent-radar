# V2.2：自由提问与可实践的学习卡

目标是让个人学习路径完整：提出一个 Agent 应用层问题，阅读短卡，选择一个小练习，并能回到来源核对。

## 已实现

- `Ask Radar` 手动工作流接受 1–600 字自由问题，用已有 GitHub Secret 调用模型；学习卡显示在运行 Overview，也保存为 `answer.md`，检索与模型诊断保存为 `run.json`。新工作流合并后才出现在默认分支的手动运行入口。
- 周报和研究回答使用 `learning_cards.py` 的同一教学契约和渲染。卡片包含定义、应用场景、学习深度、2–4 个学习点、15–30 分钟的小练习、完成标准和来源。实践时间是建议预算，不能用字段校验保证实际时长。
- 研究评测增加学习卡结构检查、Markdown 回答、模型调用次数与已记录 token 用量。每完成一个场景就保存报告，后续运行中断也能保留已完成结果。
- 自由问题通过环境变量传入 Python，不插入 Shell 代码；用户和来源文字转义后展示。引用链接仍由程序从来源记录生成。

## 验证方式

```bash
python -m pytest -q
python research_eval.py --mode replay
python research_eval.py --mode live
python ask_radar.py --question "最近 MCP 有哪些值得学的实现？"
```

本地 83 项测试通过，包含不完整教学卡、过大的练习预算、编造链接、Markdown 内容边界、自由提问成功/失败记录、超长问题、保留具体约束的查询、宽泛查询兜底、格式重试不越过步数预算，以及周报不能把不可引用的候选标题当作证据。八个合成回放通过。这些是结构与程序测试，不是八个真实答案的质量成绩。

PR 的 `research-live-suite` 标签触发八个 live 场景及一次 Weekly 预览；`ask-radar-preview` 标签触发一个自由提问示例；`weekly-learning-preview` 只运行 Weekly。均限仓库所有者创建、且分支位于本仓库的 PR。Weekly 预览不提交报告、也不发送邮件；`weekly-evidence.json` 保存模型实际收到的来源摘要。每次评测需要重新添加对应标签，提交代码不会自动消耗模型调用。

评估维度为问题相关性、引用支持、应用解释、练习范围，每项 0–2 分；这与自动结构 PASS 分开。复核由 Codex 对照本次保留的摘要和项目简介完成，未读取全文、未实际完成每个练习，也不属于独立专家评估。未配置 Tavily 时覆盖有限。

## 真实运行暴露的问题与修复

2026-10-02，所有调用均在 GitHub Actions 内使用已有 Secret；测试与预览未发送邮件、未提交自动生成的周报和趋势 state。

1. 首个 Ask 预览完成了检索，但优先使用固定别名丢失了问题中的 Python；其完成标准还增加了练习没有交代的客户端/服务端准备。首轮现在保留一条具体查询，教学提示要求完成标准仅检查练习中已经说明的步骤。
2. 首轮八场景有 7 个结构通过；Memory 返回无效 JSON。仅无效/截断/空内容可进行一次格式修复，修复计入原有步数预算，不重试鉴权或网络错误。研究回答最多三张紧凑卡。
3. 第二轮 Memory 恢复，医疗工程对比却只保留一条来源并诚实返回证据不足。两条过长查询把首轮预算用在窄搜索上。现在首轮组合一条具体查询与一条宽泛主题别名，模型提示也要求短查询；日期和相关性过滤没有放宽。
4. 周报先出现无效 JSON，加入停止原因检查后确认第二轮为 `finish_reason=length`。卡片上限缩到五张，并显式使用非思考模式为可见 JSON 保留 6,000 token 输出预算；完整停止、JSON 和教学卡校验仍然必需。失败输出不发布成学习结论，日志只保留安全的错误类型/状态。
5. 摘要复核发现医疗卡曾把强化学习控制与 LLM 团队混为一种定义，且部分 RAG 练习依赖未说明的模型/向量库。提示增加系统类型边界；小练习现在以普通本地 Python、假数据与给定 toy 排名为默认，不要求模型调用、下载或框架安装。对比问题要求披露缺少直接基线。提示不能保证这些语义要求每次都满足，残余问题见逐条复核。
6. Weekly 的候选词 `examples` 包含未进入代表性资料上限的论文标题。模型据这些标题写内容，却引用了另一篇论文。删除模型输入里的候选标题示例，候选统计只用于分类；卡片必须依据可引用的代表性摘要。原始候选统计仍保留在诊断 artifact。

接口参数依据：[DeepSeek Chat Completions 官方文档](https://api-docs.deepseek.com/api/create-chat-completion/)。配置的模型名是 `deepseek-v4-flash`，供应方可能调整该名称对应的后端；结果说明的是这次运行，不是长期可复现的模型质量分数。

## 本阶段结果

- 83 项测试和 8 个合成回放通过；最新代码的 CI 成功。
- [完整 live 场景](https://github.com/chromiii/ai-agent-radar/actions/runs/37030517257)有 8/8 个结构 PASS，24 张卡；共 20 次模型调用、95,123 个已记录 tokens，单场景 14.1–35.4 秒（中位数 17.3 秒），包含一次有限格式重试。
- [Python MCP 自由提问](https://github.com/chromiii/ai-agent-radar/actions/runs/37030519156)生成三张卡，脚本约 19.1 秒、两次调用、9,200 个已记录 tokens；[原始回答](eval/v2_2-ask-example.md)与已实际运行的[本地模拟练习](../examples/mcp_mock_dispatch.py)已保留。
- [最终 Weekly 预览](https://github.com/chromiii/ai-agent-radar/actions/runs/37032278507)生成五张卡，8,794 个已记录 tokens；剥离不可引用的候选标题后，逐卡 `why_now` 与保留摘要的错配在此样本中未再出现。首张练习仍要求编码代理生成脚本，应以手写/mock 候选替代以满足默认本地模拟范围。

上述是各自运行的用量，不是整个迭代过程的总账或金额。研究/Ask 的评测 commit 为 `c29794d`，Weekly 为 `fb1c3de`；后续收尾仅增加说明、模拟代码及窗口说明，没有重复消耗模型调用。评测在 Actions 内使用已有仓库 Secret，未向本次对话暴露密钥值。

[逐条复核](eval/v2_2-review.md)与[精简运行记录](eval/v2_2-live-summary.json)分开记录结构结果与内容评分。仍有医学对比语气过满、不同评测指标混写、RRF 完成标准过强等样本；本阶段完成个人学习入口与评测闭环，尚未证明独立语义核验或生产质量。

## 后续边界

本阶段没有增加长期学习记忆、独立语义 Verifier、LangGraph、多 Agent 或 Web UI。下一轮按本次错误样本决定检索、核验或运行恢复的改进。日报与公司雷达保持现有运行路径；Weekly 只统一学习卡契约与呈现。
